<objective>
Fix issue #36: the plugin's 18 shell-form hooks (`node -e ...`) and the stdio MCP server (`"command": "node"`) fail when Claude Code is launched without a login shell (desktop launcher, systemd unit, `terminal -e`), because the inherited PATH lacks version-manager node (pixi, nvm, fnm, volta, mise, asdf, Homebrew on a fresh Linux shell). Hooks exit 127 silently; the MCP server does not start.

Two launch paths, two fixes, both gated on `command -v node` failing so the normal on-PATH install is never changed:
1. Hooks already run under `sh -c`, so every command gets one identical POSIX preamble that probes the common install directories and prepends the first hit to PATH before the untouched `node -e` payload. The preamble references no plugin path, so the existing CLAUDE_PLUGIN_ROOT-unset cache-scan fallback (commit 7a80d47) keeps working.
2. The MCP server has no shell, so it launches through a new POSIX wrapper `bin/gsd-node` (with a `bin/gsd-node.cmd` Windows twin) referenced as `${CLAUDE_PLUGIN_ROOT}/bin/gsd-node`.

Ordering rule that the whole plan obeys: `bin/build-bm.cjs` copies every tracked source file (including CHANGELOG.md and .github/workflows/check-drift.yml) into dist/bm, so there is exactly ONE build run and it happens after the last source edit, with every new file staged first, and dist/bm goes into the same single commit.

Purpose: hooks and the MCP server work regardless of how Claude Code was launched, with zero behavior change where node is already on PATH.
Output: edited hooks/hooks.json and .claude-plugin/plugin.json, new bin/gsd-node + bin/gsd-node.cmd, new tests/hook-node-resolution.test.cjs wired into CI, a CHANGELOG Fixed entry, regenerated dist/bm twins, one commit, clean-tree gates green.
</objective>
