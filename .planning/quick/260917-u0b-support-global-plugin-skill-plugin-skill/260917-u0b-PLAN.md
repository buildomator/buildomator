<objective>
Port the documented upstream `global:<plugin>:<skill>` form into the agent_skills resolver so a Claude Code plugin skill (for example `global:superpowers:brainstorming`) can be injected into gsd-executor / gsd-planner / gsd-verifier. Today both resolver twins strip `global:` and run the remainder through `/^[a-zA-Z0-9_-]+$/`, so the colon in a namespaced name trips "Invalid global skill name" and the entry is silently dropped (empty `<agent_skills>` result).

Purpose: the namespaced form is the documented contract in upstream gsd-core CONFIGURATION.md and users following it get a rejected config. Plugin skills live in a versioned, ephemeral cache, so the fix does not resolve a filesystem path; it emits a Skill-tool load-by-name directive for the agent.

Output: both twins (sdk/src/query/skills.ts + bin/lib/init.cjs) accept the namespaced form and render the directive; personal `global:<name>` path behavior is untouched; malformed names are warned and skipped; regression tests in both suites; SDK rebuilt; dist/bm regenerated and drift-checked. No version bump, no CHANGELOG entry (release is cut separately).
</objective>

## Design decisions (fixed here so both twins match byte-for-byte)

Directive line for a plugin skill `<plugin>:<skill>` (one line, no file path):

`- Invoke the Skill tool with skill "<plugin>:<skill>" at agent start (plugin skill, loaded by name, not by path)`

Header line stays exactly `Read these user-configured skills:` (existing tests and workflows depend on it; the directive line is self-explanatory).

Namespaced name regex (declare a module-level const in BOTH twins with the same name):

`PLUGIN_SKILL_NAME_RE = /^[A-Za-z0-9_-]+(:[A-Za-z0-9_-]+)+$/`

Detection order inside the `global:` branch, after the existing empty-name guard:
1. `skillName.includes(':')` -> plugin-skill path: test PLUGIN_SKILL_NAME_RE; on failure warn `[agent-skills] WARNING: Invalid plugin skill name "<name>": expected <plugin>:<skill> with segments of letters, digits, "_" or "-", skipping` and continue. Then if runtime !== 'claude' warn `[agent-skills] WARNING: Plugin skill "<name>" needs the Claude runtime (Skill tool); runtime "<runtime>" skips it` and continue. Otherwise push a plugin-kind entry and continue. No filesystem access, no globalSkillsBase check (cline with a plugin skill hits the runtime guard first, which is the right message).
2. No colon -> the EXISTING personal-skill code path, unchanged (GLOBAL_SKILL_NAME_RE, skills dir, SKILL.md existence, symlink guard).

Warning text hygiene: new strings use ":" and "," instead of dashes. Existing em-dash warnings stay untouched. Do not put `gsd:` inside any new fixture or string (build-bm rewrites `gsd:` tokens to `bm:` in dist/bm, which would desync the dist copy of the tests). Use `superpowers:brainstorming` and `coderabbit:code-review` as fixtures.

Deferred (note in SUMMARY, not implemented): `agent_skills_security.trusted_global_roots`. It is a path-allowlist for PATH-based global skills, orthogonal to the plugin directive, and would need config-schema declarations in both schema twins plus the parity test; not cheap, so out of scope here.
