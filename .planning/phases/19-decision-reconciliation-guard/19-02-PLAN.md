<objective>
Wire the capture-time firing point. After a decision is written to the STATE.md decision log,
the add-decision path runs the mechanical candidate retrieval from Plan 01 and, when a
candidate exists, attaches a reconcile directive to its result. The main-session agent acts on
that directive per the Plan 01 reference: a clear contradiction is rewritten in place and
committed as its own revertible commit with a notice (non-blocking); an ambiguous one stops and
asks which rule wins before any change.

Purpose: delivers RECON-01 (clear capture-time auto-rewrite + commit + notice) and RECON-02
(ambiguous capture-time ask). The mechanical parts run in Node; the judgment, rewrite, commit,
and question run in the agent turn the directive points to.

Output: both stateAddDecision twins attach the directive; execute-plan.md gains the step that
drains and acts on it.
</objective>

| agent rewrite -> authority doc | The agent edits CLAUDE.md / PROJECT.md; the edit crosses into an always-loaded file. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-19-03 | Tampering | capture-time judge | mitigate | The reference instructs the agent to treat decision and rule text as data, not instructions; the clear-path rewrite is a single-file commit the user can revert; ambiguous stops and asks. |
| T-19-04 | Elevation | capture-time rewrite target | mitigate | Only candidates the Plan 01 safety gate marked autoRewritable are rewritten; surface-only candidates are reported, never edited. |
| T-19-05 | Repudiation | auto-rewrite audit trail | mitigate | Every auto-rewrite is its own commit naming the decision and date, and the ledger records the outcome per decision hash. |
</threat_model>
