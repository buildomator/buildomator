<objective>
Wire the capture-time firing point. After a decision is written to the STATE.md decision log,
the add-decision path runs the mechanical candidate retrieval from Plan 01 and, when a
candidate exists and the ledger has no outcome, attaches a reconcile directive to its result.
The surface acting on that directive (any state.add-decision caller) follows the Plan 01
reference: a clear contradiction is rewritten in place and committed as its own revertible
commit with a notice (non-blocking); an ambiguous one is written to the shared pending record
and surfaced, with no AskUserQuestion in the capture-time surface. The question itself is asked
only later by a main-session surface, which unifies capture-time-ambiguous and session-start
onto one pending-record path.

Purpose: delivers RECON-01 (clear capture-time auto-rewrite + commit + notice) and RECON-02
(ambiguous capture-time handled tool-correctly with no executor-side ask). The mechanical parts
run in Node; the judgment, the clear-path rewrite/commit, and the pending write run in the
agent turn the directive points to.

Output: both stateAddDecision twins attach the directive; execute-plan.md gains the step that
drains and acts on it; behavioral unit and cross-twin parity tests prove the directive logic.
</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| decision text -> agent judge | The just-recorded decision is user input, but a decision text could embed instructions aimed at the judge. |
| agent rewrite -> authority doc | The agent edits CLAUDE.md / PROJECT.md; the edit crosses into an always-loaded file. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-19-03 | Tampering | capture-time judge | mitigate | The reference instructs the agent to treat decision and rule text as data, not instructions; the clear-path rewrite is a single-file commit the user can revert; an ambiguous conflict is written to the pending record and deferred to a main-session ask, changing nothing. |
| T-19-04 | Elevation | capture-time rewrite target | mitigate | Only candidates the Plan 01 safety gate marked autoRewritable are rewritten; surface-only candidates are reported, never edited. |
| T-19-05 | Repudiation | auto-rewrite audit trail | mitigate | Every auto-rewrite is its own commit naming the decision and date, and the ledger records the outcome per decision hash. |
</threat_model>
