<objective>
Build the two-axis trust gate (CAT-03 safety, CAT-04 license) as pure structural checks returning verdict objects, modeled on `security.cjs` `validatePath` (`{ safe, error }`) and `scanForInjection` (`{ clean, findings[] }`). The gate consumes a catalog entry plus the catalog's policy tables; it never opens a SKILL.md and never takes model-authored text as an input, so a model cannot vouch a skill through it.

Decision on the open PATTERNS.md question: the gate ships in BOTH twins. Workflows already run the read side through `bm-sdk query agent-skills`, and Phase 17 will call assess/insert from workflows through the same CLI, so a CJS-only gate would force an SDK shell-out and break the twin-parity convention. The policy tables live in the shared JSON (plan 01), so the two implementations are thin and a parity test keeps them identical.

Purpose: success criterion 2 (rejections and flags proven by tests) and the input contract plans 03/04 build insertion on.
Output: two gate modules, two tests.
</objective>

Create `bin/lib/skill-trust-gate.cjs` ('use strict'; require `./craft-skill-catalog.cjs` for `PINNED_COMMIT_RE` and `loadCraftSkillCatalog`; no other new dependencies). Every function takes an optional `catalog` argument (default: the module-level `catalog` from the reader) so tests can pass fixtures; nothing in this file reads a SKILL.md or any path. Comments describe behavior only.

- `SAFETY_FINDINGS`: frozen object mapping code -> human message for: `publisher-not-allowlisted`, `pin-not-commit`, `scripts-unreviewed`, `scripts-review-stale`, `tier-c-hold`, `tier-b-undeclared-execution`, `tooling-license-missing`, `tooling-license-blocked`, `source-not-https`, `entry-malformed`. Messages are one line, plain English (for example pin-not-commit: "pinned_commit must be a full 40-hex commit sha; branches, tags and HEAD float and cannot be reproduced").
- `normalizeSpdx(s)`: trim, collapse whitespace; empty / non-string returns ''. Case-insensitive matching against the policy lists is done by comparing lower-cased ids.
- `classifyLicense(spdx, catalog?)` returns `{ verdict: 'allow'|'flag'|'block', spdx, category, obligations, reason }` where category is one of `permissive`, `copyleft`, `source-available`, `non-commercial`, `proprietary`, `no-license`, `unknown`. Rules: '' / NONE / NOASSERTION / UNLICENSED -> block, no-license. Id in `allow` -> allow, permissive. In `flagCopyleft` -> flag, copyleft. In `flagSourceAvailable` -> flag, source-available. In `block`: ids containing "NC" or "Noncommercial" -> non-commercial, otherwise proprietary. Anything else -> block, unknown ("not in the license policy tables; add it deliberately or reject"). Compound SPDX expressions: split on the tokens ` OR `, ` AND `, ` WITH ` (case-insensitive, surrounding parentheses stripped); classify each operand; `OR` keeps the best verdict (allow > flag > block), `AND` and `WITH` keep the worst; any unknown operand forces block. `obligations` = policy obligations for the chosen id (for compounds, join the operand lines with " | "); `reason` is one line naming the id and the category.
- `checkSafety(entry, catalog?)` returns `{ safe: boolean, findings: Array<{ code, message }>, scripts_banned: boolean }`. If `entry` is not an object with string `id`, return a single `entry-malformed` finding. Apply, in order: publisher in `Object.keys(catalog.publishers)`; `PINNED_COMMIT_RE.test(entry.pinned_commit)`; `entry.source` starts with "https://"; scripts rule: when `bundles_scripts === true`, `scripts_review` must be an object with verdict 'reviewed' or 'banned' (else `scripts-unreviewed`) and `scripts_review.commit === entry.pinned_commit` (else `scripts-review-stale`), and verdict 'banned' sets `scripts_banned = true`; tier rules: 'C' -> `tier-c-hold`; 'B' with `bundles_scripts === false` and empty `tooling` -> `tier-b-undeclared-execution`; tooling rule: each tooling item needs a non-empty license (else `tooling-license-missing`) and `classifyLicense(item.license).verdict !== 'block'` (else `tooling-license-blocked`, message names the tool). `safe = findings.length === 0`.
- `assessEntry(entry, catalog?)` returns `{ id, verdict, safety, license, tooling: Array<{ name, license, verdict, category }>, scripts_banned, publisher: { id, label } | null, pinned_commit, source, skill_path, trust_tier, prompt: string[] }`. `verdict` = 'block' when `!safety.safe` or `license.verdict === 'block'` or any tooling verdict is 'block'; else 'flag' when `license.verdict === 'flag'` or any tooling verdict is 'flag'; else 'allow'. `prompt` is the insert-prompt content as an array of lines, in this order: "<id>: <summary>", "Publisher: <label>" (or "Publisher: NOT ON ALLOWLIST (<publisher>)"), "License: <spdx> (<category>, <verdict>)", "Obligations: <obligations>", one "Tooling: <name> <license> (<verdict>)" line per tooling item, "Trust tier: <A|B|C>; bundled scripts: <none | reviewed at pin | BANNED, do not execute>", "Pin: <source> @ <pinned_commit> (<skill_path>)", then one "Finding: <message>" line per safety finding, and a final "Verdict: <allow|flag|block>" line. No endorsement wording anywhere (labels come from the catalog; the gate adds none).
- `renderAssessment(assessment)` returns `assessment.prompt.join('\n')`.
- `module.exports = { SAFETY_FINDINGS, normalizeSpdx, classifyLicense, checkSafety, assessEntry, renderAssessment }`.

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| catalog entry -> gate | Curated metadata in; verdict out. No skill text crosses |
| third-party skill body | Never read by the gate; only ever read by the one target agent after a human accepts (plan 03/04) |
| model -> gate | The gate has no free-text input a model could use to vouch; only structured entry fields |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-16-06 | Tampering / Elevation | malicious skill body or bundled scripts | mitigate | Gate never opens SKILL.md (acceptance: no fs calls); bundles_scripts requires a review record at the exact pin or a ban; tier C always holds; tier B must declare its execution surface (checkSafety) |
| T-16-07 | Tampering | floating-ref swap (pin bypass) | mitigate | pin-not-commit finding for anything that is not a full sha; scripts-review-stale when the review commit differs from the pin (Task 1); runtime HEAD comparison is added at insert time in plans 03/04 |
| T-16-08 | Repudiation / Information Disclosure | license laundering (relabeling a blocked source as MIT, or hiding tool licenses) | mitigate | Classifier runs on catalog SPDX with a closed policy table (unknown -> block, compound expressions resolve conservatively); tooling licenses are classified independently and can block on their own; obligations and license_url surface in the prompt |
| T-16-09 | Spoofing | model-vouched safety bypass | mitigate | Verdict is a pure function of structured fields and policy tables; no text argument, no network, no file read; human approval happens outside the gate (plan 03/04 --approved) and is recorded |
| T-16-10 | Spoofing | publisher outside the allowlist | mitigate | publisher-not-allowlisted finding blocks the assessment |
| T-16-SC | Tampering | npm/pip/cargo installs | accept | No package installs in this plan |
</threat_model>
