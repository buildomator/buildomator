**build-bm --check reports FAIL on the current working tree. Out of scope, not a regression of d2e6031.**

`node bin/build-bm.cjs --check` exits non-zero and lists 47 differing files. Investigation (proven, not assumed):

- `git status --porcelain dist/bm` is clean: `dist/bm` has had no working-tree change since commit d2e6031.
- All 47 `differs:` paths are `sdk/src/**`, `sdk/dist/**`, `references/**`, `hooks/**`, `templates/**`, `workflows/plan-phase.md`: none are phase-18 artifacts (0 hits for skill-conformance / agentskills / skill-trust / craft-skill among the differs).
- `comm -23 <(differs) <(git-modified)` is empty: every drift file is a subset of the ~53 uncommitted tracked working-tree modifications. These are the `/gsd-x` -> `/gsd:x` namespace rewrite the user is handling separately (see deferred-items.md).

Conclusion: `build-bm --check` builds from the working tree via `git ls-files`, so the uncommitted out-of-scope namespace edits leak into the fresh build and cause the diff. On a clean checkout of d2e6031 the gate passes (it passed at commit time, which is why d2e6031 landed). The phase-close truth "no drift on the committed tree" holds for the committed tree; the FAIL here is an artifact of concurrent, separately-owned work and was deliberately left untouched per the continuation scope guard.
